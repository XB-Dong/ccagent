# P4.2 冻结规格 · p42-v1

仅任务清单的展示层归组。输入 Snapshot.tasks 沿用现有 Task 类型，createdAt 仍为服务端持久创建时刻；没有新 API 或存储字段。

1. 新纯函数放 apps/web/task-groups.ts：按所选 IANA 查看时区将任务 createdAt 归到日历日期，返回日期组和原任务对象；日期组新到旧，组内按真实创建瞬间新到旧，相同时刻按 id 稳定排序。空输入返回空；无有效 createdAt 的旧记录放末尾未知日期组，不用 updatedAt/dueAt/completedAt 补猜。输入数组和任务不可原地改写。
2. TasksPage 仍先用既有待处理/全部记录规则筛选，再归组。每组显示“某日创建”和组内数量；查看时区默认 Asia/Shanghai，用既有中文 timeZones 选择，可选 Europe/Rome。明确“按创建日期归组；查看时区仅影响显示”。切换不写 API，不改变任务自身时区或时刻。
3. 编辑、确认草稿、清单勾选、记录完成/实际分钟和取消流程沿用；TaskForm 保持在分组外，周期快照不覆盖输入。工作日历继续按 completedAt；原计划时间展示仍用任务 timeZone。旧无创建日期任务依旧可操作。
4. 用户可见文案中文；复用现有样式，确需样式放 p42-tasks.css，避免通用 CSS 污染。不增加依赖、月历视图、自动改任务日期、外部日历同步或模型调用。
5. 行为验收覆盖跨 UTC 日界、Rome 冬夏/跨日、数值时间排序、编辑/完成不移动创建组、未知日期不丢行、原输入未改变。浏览器验证既有状态筛选、查看时区切换及分组可见，编辑/完成后仍在原创建日期下。没有声称模型链路或真实业务数据被本轮重新验收。

Leader 独占需求/计划/状态/共享文档与发布；开发者仅写 TasksPage、task-groups、专用样式与对应测试；审核者只读。验收缺口如实记录，必要测试不设置人为累计费用/次数/token 限制；本轮未改变模型契约，不为纯显示规则付费冒烟。
