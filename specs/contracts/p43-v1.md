## Task details

`cc_get_task` / Business.tool action `get_task`: `{taskId: string, offset?: integer>=0}`. Scoped existing task only. Return `{task:{id,revision,title,timeZone,createdAt,status,startAt?,endAt?,dueAt?}, checklist:string[], checked:boolean[], totalItems:number, nextOffset:number|null}`. Page size 4; preserve full text without truncating steps; serialized UTF-8 response <=6000 bytes or explicit error. Validate scope/kind/offset; no writes, queue drains or model calls from reads.

## Draft copy

UI `POST /api/actions/task-copy`: `{requestId, taskId, revision, title?, replaceFrom?, replaceTo?}` returns full Task. Model `cc_copy_task` / Business.tool action `copy_task`: same except requestId is supplied deterministically by the server using current user source plus payload. Model result is a bounded confirmation `{id,revision,title,status,timeZone,totalItems}` (UTF-8 <=6000 bytes); full steps remain available through paged get_task. Pre-implementation clarification accepted from independent review: returning all copied steps could exceed the model context boundary.

Only those fields allowed. revision is a positive integer matching the source at creation. Optional title is the replacement base title; absent uses original. replaceFrom/replaceTo must either both be absent or both nonempty strings <=100 characters. Apply case-sensitive literal replacement to base title and every checklist item, including regex punctuation literally. Final title 1..200, checklist 1..30 nonempty strings each <=300, same as existing tasks. No arbitrary code or external writes.

Create new Task with new id/createdAt, original timezone, draft status, all checked false, confirmedSuccess false; omit dueAt/startAt/endAt/completedAt/actualMinutes. sources must include original task id and current request source id. Original task unchanged. Preserve deletion closure and receipt revocation. Repeated identical request returns original copy; same UI requestId with a changed payload raises COPY_REQUEST_CONFLICT; same model source and payload is idempotent. Identical replay may succeed after source revision changes, but deleted origin/revoked receipt must not resurrect. Reject stale revision for new copy, other scopes, wrong kind and invalid fields. Do not nest Store.once transactions or create unused capture jobs when validation fails.

## UI

Task card offers 复制为新任务 for all task states. Opening freezes task revision, previews full steps and optional title/literal replacement. Confirm copy creates a draft and shows clear next step; original unchanged; no automatic execution. Retry keeps requestId until edits change payload. Busy guards prevent duplicate clicks; Chinese user-friendly conflicts; stale source requires refresh/reopen.

Task list uses Asia/Shanghai for group date and every displayed task timestamp, explicitly 北京时间. Date input filters by original creation day, with 全部日期 and clear empty selected date group. Status filter applies first. Unknown creation dates show only in all-date view after known groups. Do not synthesize dates for unknown records. Stable task card keys retain minute/editor input. Underlying stored timezone/schedule and TaskForm/WorkCalendar timezone semantics unchanged. No arbitrary manual ordering in this wave.
