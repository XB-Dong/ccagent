# ADR 0002 · 业务需求独立与双路沉淀

日期：2026-10-26｜状态：需求独立为用户明确决定，自适应策略为设计提案

## 原选择与变化

旧业务只存在对话交接。用户明确要求 cc 的需求独立成文、可按日期追加，且与 AI Coding 宪法区分；同时要求自动整理不满反馈与工作经验 Skill。

## 决定

- [业务总览](../product/REQUIREMENTS.zh.md)保存当前需求；[日期追加](../product/changes/README.md)保存每次变化。宪法只保存工程方法和约束。
- 反馈形成候选迭代需求，成功流程形成 Skill；会话压缩、结构化业务记忆和研发记录分别管理。
- 自动捕获/归并/提炼不需要 cc 每次手动整理。自动启用限制为验证通过的低风险范围；更高风险确认策略在 R0 定稿。
- 产品运行时不直接编辑或推送代码仓库；需求导出为脱敏审阅包，再在获授权的研发任务中追加文档。

## 后果与待确认

可追溯来源、纠正/撤销、删除传播、范围隔离和重试幂等成为 P0 必须设计并验证的行为。保留期、触发阈值和低风险自动启用政策尚未逐项得到用户确认，不能写成已批准事实。
