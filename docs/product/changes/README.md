# 业务需求日期记录

当前总览：[REQUIREMENTS.zh.md](../REQUIREMENTS.zh.md)。本目录保存追加记录，与 AI Coding 宪法独立。

文件名使用 `YYYY-MM-DD.md`，同一天新增带时间和递增编号的条目；已记录条目只允许修正排版，内容更正另加一条。跨天新建文件。时间为 Asia/Shanghai，明确记录时刻与原始提出日期；历史提出时间未知就写未知。

每次变更流程：

1. 捕获来源与原意，分配稳定需求 ID；自动识别先标候选。
2. 在日期文件追加条目：变更 ID、记录时间、来源、类型（新增/修改/撤回/优先级）、需求及版本、原值/新值、理由、确认状态、影响规格/验收/波次。
3. 更新需求总览并递增版本，保留指向日期记录的链接。
4. 如果影响已冻结规格，由 Leader 写决定并同步测试/任务包；尚未批准的需求不触发自动开发。

2026-10-26 每日迭代授权补充：明确、范围内的工作台建议可由 Leader 自主采纳并按本流程形成确认记录；不需要逐项人工审批。歧义或权限扩大的内容仍待确认，单纯被系统捕获不等于已采纳。

条目模板见[需求变更模板](../../templates/requirement-change.md)。Git 历史辅助追踪，日期记录直接供人阅读；两者都不是不可篡改审计承诺。产品运行中采集的私密原文放业务存储，代码库只保留明确获准的脱敏需求。
