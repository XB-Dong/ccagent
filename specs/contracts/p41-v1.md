# P4.1 冻结契约 · v1

Leader 单写；基于现有 JSON 实体、Store 乐观锁和鉴权 API，不需要 SQL 迁移。所有正文只作为数据，不授予执行权限。

## 任务与工作记录

- Task 新增可选 `startAt`、`endAt`、`completedAt`（带明确偏移的 ISO 时刻），`actualMinutes`（0–1440 的整数，null/缺省代表未知）。既有 `dueAt` 保留；新设置 endAt 时与 dueAt 同步，清除 endAt 时清除 dueAt，未提交该字段不改旧 dueAt。
- TaskInput 接受可选 startAt/endAt；create 校验时区、日期时间及 start < end（两者存在时）。任务已绑定 source，创建仍幂等。
- Tasks.update 允许活跃状态 draft/open/in_progress 的标题、清单、时区与计划时间编辑；同一 ID/来源不变，时间字段 null 可清除。新增/修改的检查项 checked 变 false，只有相同位置相同文本才保留既有 checked。不得同次任意注入结构外字段。完成/取消后结构不可改，已完成任务仅可修正 actualMinutes。
- task-update 的 status/checked/confirmedSuccess 沿用既有状态门槛。第一次进入 done 设置服务端 completedAt，不接受客户端指定完成时刻；后续更新保持。只有 confirmedSuccess 从 false 到 true 时可产生一次 workflow job；重复提交旧 revision 冲突，无新派生。任务完成后自动按 Task 实体在日历呈现，不再复制日历记录。
- startAt/endAt/dueAt 若给出必须有效，已知显式偏移必须与 IANA 时区当地时间相符（复用 zonedInstant）；无偏移/非法日期拒绝。时区变更必须提交与新时区匹配的计划值，不能悄悄偏移既有瞬间。
- UI 日期输入 + 每 15 分钟的时间下拉（允许保留旧分钟），start/end 均可选；采用 IANA 当地时间转换，Europe/Rome 冬夏令时均正确，跳时和重叠歧义拒绝并提供中文提示，不猜偏移。转换 helper 放 apps/web/task-time.ts，纯函数可离线测试。
- 工作日历按用户所选 IANA 时区/日期分组 completedAt；显示任务名、完成时间、实际分钟和计划时间，并合计已记录实际分钟，明确未记录数。旧 done 无 completedAt 时单列“历史完成记录，日期未记录”，不使用 updatedAt 冒作完成时间。无自动计时/后台监视，不把计划时差作为实际值。日历可采用可选择日期的逐日记录视图，不必新引图表库。

## 学习笔记

- 新实体 kind `note`，Note 类型：Base + title:string + content:string。标题 1–200 字符，正文 1–10000 字符。创建/更新通过服务端 safeText；纯文本 React 渲染，不执行 HTML/指令，不进入模型/Skill 上下文。
- Notes.create(scope,key,{title,content}) 用 Store.once；Notes.update(scope,id,revision,{title,content}) 校验 kind/范围/修订；Notes.remove(scope,id,revision) 校验后走已有隐私删除机制，避免恢复复活，不记录私密正文到研发证据。
- Leader 集成补充（01:12 审阅）：手动笔记从未进入模型上下文，其删除使用显式 `delete-note` 隐私账本事件，保留引用闭包和恢复重放；不退休无关的旧会话/摘要。仅 kind=note 能请求此事件，其他来源仍走原 delete 规则。此为现有隐私机制的限定扩展，不赋予产品额外权限；需独立审核与备份重放测试。
- 独立审核补充：delete-note 的已应用标记使用 `closure-v3-note` 命名空间，旧 delete/revoke 保持 closure-v2，避免旧版读者把未知事件标已处理后阻止新版真正删除。恢复工具必须采用 P4.1 或更新的隐私重放版本；旧代码只允许在已处理的当前数据上回退，不以旧恢复器替代新规则。
- 手动 API 动作为 `note`（含 requestId）、`note-update`、`note-delete`（均含 id/revision）。快照增加 notes:Note[]。UI NotesPage 使用 data/mutate/busy，搜索在本地数据内，提交失败保留表单。
