# ADR 0001 · 项目基线与当前授权

日期：2026-10-26｜状态：用户方向已确认，实施细节为提案

## 原选择与变化

旧交接的简单网页/Python 技术栈与先做活动的排序均未定稿。用户本轮明确本地目录 `.`、在 XB-Dong 新建私密仓库，并指定官方 DeepSeek Harness 与自适应沉淀目标。

## 决定

1. 新仓库名采用与目录一致的 `ccagent`；private=true。采用单仓库，不复制旧业务系统源码。
2. 本轮完成 P0 前置：文档、规范、上游调研、任务草案、检查和仓库发布。不启动产品开发或服务器部署。
3. 工程流程参考 classroom-annotator 和 AI Coding 范式；旧项目技术栈、模型、截止、授权和凭据不继承。
4. 提案以 Harness 插件/profile 扩展为主；Node/TypeScript 与上游保持一致，SQLite 业务存储、UI seam 和产物方式在 R0 验证。

## 后果

P0 提案优先底座与自适应最小闭环，完整库存/活动/发货/广告能力在业务文档保留。用户可按试用反馈调整波次；尚未完成的能力显式标记规划中。

## 2026-10-26 追加决定 · 连续自主推进覆盖旧逐波审批

来源：用户明确要求后续统一 P1/P2/P3，P0 后 Leader 自主决定进入下一波；每波像 P0 一样先生成计划再执行，无需人工审批，最后由用户验收完整项目结果和 report；当前先沉淀到已有 Markdown 并报告。

新决定：正式开始项目后按 P0 → P1 → P2 → P3 连续推进，Leader 自行计划、依赖评估、审阅/冻结和进入；每波报告继续保留，但不再作为人类逐波批准的等待点。路线将活动与最低数据接入归 P1，库存补货与发货协同归 P2，广告及完整集成交付归 P3；只是模块编排调整，没有删除原有需求。具体每波范围由 Leader 按真实依赖制定。

覆盖：宪法、AGENTS、P0 计划和 Release 任务中旧“波次报告后停止、等待用户决定下一波”的常规要求。历史报告和事件作为当时事实保留，不回改。业务需求正文、候选状态、模型额度节约、验收真实性、数据/外部权限边界不变。

本次动作边界：仅文档/状态更新及私密仓库同步；没有生成虚假的未来详细计划，没有启动 P0/P1/P2/P3、付费模型调用或服务器操作。后续任务在正式开始后依此长期授权推进，只有用户停止、约束到达或必要外部依赖无法推进时才报告并等待相应输入。
